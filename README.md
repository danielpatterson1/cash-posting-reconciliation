# Cash Posting Reconciliation

**[Open the live dashboard](https://danielpatterson1.github.io/cash-posting-reconciliation/)** | Built with R, DuckDB SQL, Parquet and R Markdown | **100% synthetic data**

A daily reconciliation that matches every bank deposit to the payments posted in patient accounting, routes each exception to the team that owns it, and tracks how much cash is sitting unposted and for how long.

> All data in this repository is randomly generated by `R/generate_synthetic_data.R`. No real patients, accounts, payers, facilities or bank references are represented.

## Problem

Cash arrives at the bank as EFTs and lockbox checks, then has to be posted line by line to patient accounts. When the two sides drift apart (lines posted late, keying errors, duplicates, checks posted without a bank reference, or deposits never posted at all), unposted cash ages quietly. A manual morning review of the deposit log catches some of it, but it depends on one person and does not show trends.

## Approach

1. **Synthetic sources:** about 3.4K deposits over six months and about 21K posting lines, with planted scenarios: late lines, keying errors, duplicates, missing references and unposted deposits. A daily report "launches" in August, after which the backlog is worked down and new exceptions resolve faster.
2. **Standardize (R):** parse dates and amounts, normalize references, attach payer owners, and write Parquet.
3. **Match (DuckDB SQL), in passes:**
   * Pass 1: postings that carry the bank trace or check number
   * Pass 2: lockbox batches posted without a reference, matched on payer, exact amount and a 10 day window, closest date first, each batch used once
   * Pass 3: everything left becomes an open item, classified as no matching posting, partial posting, amount variance, or over posted
4. **Rebuild history:** recompute the unposted position for every business day from posting dates, so the effect of the daily report is measured rather than estimated.
5. **Validate:** 8 checks gate the render, including a full tie out (posted plus unposted equals deposited) and a trend that ties to today's open items.

```
bank_deposits.csv + postings.csv  →  R/etl.R  →  Parquet  →  sql/match_deposits.sql  →  sql/daily_unposted_trend.sql  →  R/validate.R  →  index.html
```

## Stack

R, dplyr, Arrow and Parquet, DuckDB SQL (window functions, multi pass matching), R Markdown, flexdashboard, Plotly, DT, crosstalk, GitHub Pages

## Results

On the synthetic data set:

* **97%** of deposits, and of deposit dollars, match to postings automatically
* About **90** open deposits remain, each with an owner, a reason and an age
* Unposted cash older than 30 days falls about **90%** in the three weeks after the daily report launches
* Lockbox checks posted without a bank reference are still matched by payer, amount and date
* **8 of 8** data checks passing on every run

## How to run

Requires R 4.3 or later and pandoc (bundled with RStudio or Quarto).

```r
install.packages(c("dplyr", "arrow", "duckdb", "DBI", "rmarkdown",
                   "flexdashboard", "plotly", "DT", "crosstalk"))
```

Then from the project folder:

```bash
Rscript run_pipeline.R
```

This regenerates the raw files, runs matching and checks, and writes `index.html`. The seed is fixed, so the output is reproducible.

## Project layout

| Path | Purpose |
|:---|:---|
| `R/generate_synthetic_data.R` | Seeded generator for bank and posting files with planted exceptions |

| `sql/daily_unposted_trend.sql` | Daily unposted cash rebuilt from posting history |

| `recon_dashboard.Rmd` | The dashboard |
